## Описание проекта
Веб-приложение на базе современного асинхронного веб-фреймворка FastAPI, реализующее полный жизненный цикл CRUD-операций, специализированные модели ответов Pydantic (`response_model`) и централизованную обработку исключений с использованием класса `HTTPException`.

### Основной функционал:
1. **CRUD-операции для задач (`/todo`):**
   - `POST /todo` — создание новой задачи с кодом состояния `201 Created` и валидацией через `Todo`;
   - `GET /todo` — получение списка задач через модель ответа `TodoItems` (скрытие `id` при выдаче);
   - `GET /todo/{todo_id}` — получение единичной задачи по ID с генерацией `404 Not Found` при отсутствии;
   - `PUT /todo/{todo_id}` — обновление задачи через модель `TodoItem` с генерацией `404 Not Found`;
   - `DELETE /todo/{todo_id}` — удаление отдельной задачи с генерацией `404 Not Found`;
   - `DELETE /todo` — групповое удаление всех задач из списка.
2. **Модели ответов (`response_model`):**
   - Разделение входных моделей сущностей и выходных контрактов ответа;
   - Предотвращение утечки служебных полей (`id`) при выдаче клиенту;
   - Автоматическая валидация схемы в Swagger UI и OpenAPI спецификации.
3. **Обработка ошибок (`HTTPException`):**
   - Возврат семантических HTTP-статусов вместо универсального 200 OK;
   - Код `404 Not Found` при обращении к несуществующему ресурсу;
   - Код `400 Bad Request` при коллизии ресурсов;
   - Код `422 Unprocessable Entity` при невалидной структуре входного JSON.
4. **Персональная тема (Управление сетевыми узлами `/nodes`):**
   - Регистрация, просмотр топологии, обновление статуса и вывод из эксплуатации сетевых узлов;
   - Полное покрытие CRUD-действий и валидация ошибок сетевых адресов.
5. **Персонализация ответов:**
   - Все статусные сообщения и ошибки персонализированы (Митрофанов Лев).

## Запуск приложения

```bash
# 1. Активация виртуального окружения
python -m venv venv
source venv/bin/activate  # Для Windows: venv\Scripts\activate

# 2. Установка зависимостей
pip install -r requirements.txt

# 3. Запуск сервера разработки
uvicorn api:app --port 8000 --reload
```

## Тестирование API с помощью curl

```bash
# Приветственный маршрут
curl http://127.0.0.1:8000/

# Создание задачи (POST со статусом 201)
curl -X POST http://127.0.0.1:8000/todo \
  -H "Content-Type: application/json" \
  -d '{"id": 1, "item": "Разработать CRUD API на FastAPI"}'

# Получение списка задач через response_model (только поле item)
curl -X GET http://127.0.0.1:8000/todo -H "accept: application/json"

# Обновление задачи (PUT)
curl -X PUT http://127.0.0.1:8000/todo/1 \
  -H "Content-Type: application/json" \
  -d '{"item": "Разработать CRUD API и настроить обработку ошибок"}'

# Запрос несуществующей задачи (проверка HTTPException 404)
curl -i -X GET http://127.0.0.1:8000/todo/999 -H "accept: application/json"

# Удаление отдельной задачи (DELETE)
curl -X DELETE http://127.0.0.1:8000/todo/1 -H "accept: application/json"

# Регистрация узла сети (Персональная тема)
curl -X POST http://127.0.0.1:8000/nodes \
  -H "Content-Type: application/json" \
  -d '{"id": 1, "hostname": "edge-router-01", "ip_address": "192.168.1.1", "role": "gateway", "status": "active"}'
```
